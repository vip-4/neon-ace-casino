Canvas engineering note

3×5 slot reels, a Big Win blast, and a crisp Retina fix

A runnable, framework-free HTML5 Canvas demo: five reels by three rows start with cubic ease-in acceleration, hold a constant scroll speed, then stop one after another with back-out easing. Wins trigger a full-screen celebration with a dimmed backdrop, parabolic coin particles and a count-up number. The whole thing is DPR-aware and uses a clamped, fixed-timestep deltaTime so it never lurches when you return to the tab.

This is a presentation-layer prototype. There is no wagering, and the browser does not decide wins — outcomes arrive through a replaceable provider interface.

1 · Reel motion: accelerate → cruise → back-out stop

Each of the five reels holds a float offset measured in symbol units. Velocity is in symbols per second. A reel draws the symbol at (floor(offset) + row) mod 8, and the fractional part of offset shifts every cell upward by that fraction of one row step. Drawing one extra row above and below the visible three prevents any gap from appearing mid-scroll.

Phase A — acceleration (0.55 s)

v = MAX_V · t³ with MAX_V = 19 symbols/s. Cubic ease-in means the first 0.2 s barely moves and the last 0.2 s does most of the work — exactly like a motor overcoming inertia. A linear ramp would feel like a hard clutch engagement.

Phase B — constant scroll

offset += v · dt at fixed velocity. A faint translucent streak per row suggests motion blur without real per-pixel blurring, which would blow the fill-rate budget on mobile.

Phase C — sequential back-out stop

Reels stop 0.17 s apart. With c1 = 1.70158 and c3 = c1 + 1: 

easeOutBack(t) = 1 + c3·(t−1)³ + c1·(t−1)²
offset = from + (target − from) · easeOutBack(t)

Because the curve exceeds 1 near t ≈ 0.7, the reel physically overshoots the payline and springs back — the mechanical latch feel. target is computed so the requested symbol lands on the centre row, and at least two extra symbol units are added so a reel never snaps to a halt.

State machine

The machine-level flow is IDLE → SPINNING → STOPPING → SETTLE → WIN_PRESENTATION → IDLE. The outcome request is fired in parallel with the spin; reels only begin stopping once both the minimum spin time has elapsed and the outcome has arrived. A slow backend therefore keeps the reels turning instead of freezing them.

2 · Big Win: dim, parabolic coins, count-up number

A second, fixed, full-screen canvas sits above the page with pointer-events: none so it never eats button clicks. Three things happen together over 3.6 seconds:

  1. Background dim — an rgba(3,10,8,α) fill whose alpha is tweened in over 0.28 s and out over the last 0.55 s.
  2. Coin burst — three emission waves at 0.05 s, 0.42 s and 0.85 s. Coins spawn just below the bottom edge with an upward-biased angle and speed 620–1240 px/s; gravity is 1500 px/s², so each follows y = y₀ + v_y·t + ½g·t². Spin and alpha fade as they fall back.
  3. Number tween — the payout counts from 0 to the result with easeOutCubic, so it sprints early and eases into the exact final figure. Formatting uses one cached Intl.NumberFormat instance, not a fresh one per frame.

The "BIG WIN" heading scales in with the same easeOutBack as the reels, which ties the celebration visually to the stop. Web Audio plays a four-note arpeggio, but the AudioContext is only created on the first user gesture — browsers block audio before that, and creating it on page load just leaves a suspended context.

3 · DPR scaling and the deltaTime fix

Why Retina looks blurry

A canvas has two sizes: its CSS box and its backing store. If you only set CSS width/height, the browser stretches a 1× bitmap across a 2× or 3× display. Fix both: 

var dpr = Math.min(devicePixelRatio || 1, 2.5);
canvas.width  = Math.round(cssW * dpr);
canvas.height = Math.round(cssH * dpr);
canvas.style.width  = cssW + 'px';
canvas.style.height = cssH + 'px';
ctx.setTransform(dpr, 0, 0, dpr, 0, 0);  // 之後都用邏輯座標畫

Here the board is authored once at a fixed logical size and scaled by scale = cssW / boardW, so the effective transform is setTransform(dpr·scale, 0, 0, dpr·scale, 0, 0). The symbol atlas and coin sprite are re-rendered at the new DPR on every change. DPR is capped at 2.5: a 3× phone would otherwise allocate nine times the pixels and halve the frame rate for a gain nobody can see. A matchMedia('(resolution: …dppx)') listener catches the case where the window is dragged to a monitor with a different density.

Why it lurches after switching tabs

requestAnimationFrame is throttled or paused in a hidden tab while performance.now() keeps counting. On return, one frame can carry a delta of several seconds, so positions integrate in a single giant step — the "暴衝". The fix has three parts: 

// 1) 單幀 dt 鉗制
dt = Math.min((now - lastTime) / 1000, 0.05);

// 2) 固定時間步長積分（物理與幀率解耦）
accumulator += dt;
while (accumulator >= 1/120 && steps < 8) {
  update(1/120); accumulator -= 1/120; steps++;
}
if (steps === 8) accumulator = 0;   // 防止死亡螺旋

// 3) 分頁切換時重設時間基準
document.addEventListener('visibilitychange', function () {
  if (document.hidden) { cancelAnimationFrame(raf); lastTime = 0; accumulator = 0; }
  else { lastTime = 0; accumulator = 0; requestAnimationFrame(frame); }
});

Fixed steps also make the coin physics deterministic regardless of whether the device renders at 60 Hz or 120 Hz. An IntersectionObserver additionally skips reel drawing when the demo scrolls out of view while the state machine keeps running.

Where the frame budget goes

  • Zero allocations in the loop — a 200-slot coin pool is allocated once; emission reuses inactive slots and silently drops particles when full.
  • Offscreen sprite atlas — eight symbols are rasterised once, then blitted with drawImage; no per-frame path or text work.
  • Fewer state switches — coin rotation uses setTransform directly instead of 200 save/restore pairs; shadowBlur is applied to two text draws per frame, never per particle.
  • Precision hygiene — offset is reduced modulo the symbol count once all reels settle, so long sessions never accumulate float drift.

Architecture & the security boundary

The file assets/slot-machine.js is a single IIFE split into OutcomeProvider, Reel, CoinPool, BigWinFX, ViewManager-style resize logic and SlotMachine. It stays one request on purpose — for a demo this size, module splitting would add round-trips without improving cacheability.

The client never computes RNG or payout. The included DemoOutcomeProvider simply replays a fixed, pre-written script of outcomes; it contains no probability or paytable code. A commented ServerOutcomeProvider shows the production shape: POST /api/spin returns { stops, win, bigWin, requestId, signature } and the client only animates it. Any real-money deployment also needs server-held balances, signed results (or commit–reveal with a server seed) and rate limiting.

Everything runs under a strict Content-Security-Policy with script-src 'self': no inline scripts, no eval, no third-party origins. Reduced-motion users get shorter phases and a 20-coin burst instead of 210.

FAQ

Is this a real-money slot machine?
No. It is a free animation prototype with virtual credits only; no deposits, wagers or cash payouts.
Does the browser decide wins?
No. The demo replays a fixed script of outcomes through a replaceable OutcomeProvider. Production must use a server-authoritative endpoint for RNG, payout and signing.
Why was my Canvas blurry on an iPhone Retina screen?
The backing store was sized in CSS pixels. Size it by devicePixelRatio and call setTransform(dpr,0,0,dpr,0,0); this demo caps DPR at 2.5 to protect fill rate.
Why does the animation jump after switching tabs?
Hidden tabs pause requestAnimationFrame but not the clock. Clamp dt to 0.05 s, reset the time base on visibilitychange, and integrate with a fixed 1/120 s step.
Which libraries does it use?
None — vanilla ES6+, Canvas 2D, Web Audio API and OffscreenCanvas with a fallback. No build step and no runtime network requests after load.
Is it accessible?
Canvases have text alternatives, controls are native 44 px buttons, status changes announce through aria-live, and prefers-reduced-motion shortens the show.
